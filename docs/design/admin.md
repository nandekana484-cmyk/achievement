# 管理画面(ログインとマスタ)の設計メモ

開発指針(docs/spec.md)の 7.2 と 9(認証(管理))の、実装の判断の理由。
対象は `backend/app/api/admin.py`・`admin_masters.py`、`backend/app/services/admin_auth.py`・`admin_masters.py`・`audit.py`、`backend/app/domain/passwords.py`、`frontend/src/admin/`。
実績の訂正と24時間の日報は、次の回で作る。

## 管理者

- 管理画面に入れるのは、operators のうち role が admin で、有効な作業者だけ(既存アプリの workers の役割をそのまま使う)
- 管理者かどうかは、ログインのときだけでなく、管理画面の要求のたびに確かめる。既存アプリで admin でなくなった・無効になったら(計画の同期で反映)、ログイン中でも次の操作で 401「管理画面を使う権限がありません」になり、そのセッションは消す
- パスワードは既存アプリに無いので、本アプリで持つ(admin_credentials)

## パスワード(domain/passwords.py)

- 標準ライブラリの `hashlib.scrypt` でハッシュにする(依存ライブラリを足さない)。ソルトは管理者ごとに `secrets` で作る。保存する形は `scrypt$n$r$p$<ソルト>$<ハッシュ>` で、強さを変えても古いハッシュを確かめられる
- 平文やそのままの値は、DBにもログにも audit_log にも残さない(audit_log には「(変更)」とだけ残す)
- 8文字以上、256文字以内。UTF-8 にできない文字は断る
- 最初の設定とリセットは開発用コマンドで行う。入力した文字は画面に出さない(`getpass`。2回入れて確かめる)。パスワードを聞く前に、管理者かどうかを確かめる

```powershell
# 開発中(backend フォルダ、venv の中)
python -m app.cli admin set-password --worker-id K0042
# 担当者PC(exe と同じフォルダの GenbaCli.exe。詳細: packaging.md)
C:\GenbaApp\app\v1.0.0\GenbaCli.exe admin set-password --worker-id K0042
```

- `--stdin` を付けると、標準入力の1行目をパスワードにする(画面の確認の自動化用。PowerShell 5.1 から渡すと先頭に BOM が付くので、BOM 付きの UTF-8 として読む)
- 管理画面から、自分のパスワードを変えられる(今のパスワードが要る)

## ログインとセッション(services/admin_auth.py)

- `POST /api/admin/login {worker_id, password}`。作業者IDは今までと同じく正規化して照合する(全角・半角、大文字・小文字)
- 失敗の理由は区別しない(「作業者IDかパスワードが違います」)。作業者IDが無いときも同じだけ時間をかける(ダミーのハッシュを確かめる)ので、時間でも分からない
- 同じ作業者IDで続けて5回間違えたら、5分間ログインできない(429。回数と時間は config.toml の `[admin]`)。IDが無くても数える(IDがあるかどうかを、締め出しの有無で分からないように)。成功すると数え直す
- 成功したら、`secrets.token_urlsafe(32)` のセッションの値を作り、Cookie(`genba_admin`)で渡す。サーバーには値の SHA-256 だけを持つ(DBが漏れても、そのままではログインに使えない)
- 操作が無い時間が `[admin] idle_minutes`(既定30分)を超えたら切る。ログインから `max_hours`(既定12時間)で、操作していても切る。最後の操作の時刻は、書き込みを減らすため1分ごとに書く
- パスワードの確かめ(時間がかかる)は、本アプリのDBの書き込みのロックの外で行う(現場のボタン操作を待たせないため)

### Cookie の属性

- `HttpOnly`: 画面のスクリプトから読めないようにする
- `SameSite=Strict`: 別のサイトのページからの要求に Cookie を付けない
- `Path=/api/admin`: 管理画面のAPIにだけ付ける
- **`Secure` は付けない。** 本アプリは社内LANの HTTP で動かす(開発指針 9: フェーズ1は HTTPS を使わない)。Secure を付けると、ブラウザは HTTP では Cookie を送らないので、ログインできなくなる。社内LANの中だけで使う前提で、HTTPS にしたら Secure を付ける
- 有効期限は付けない(ブラウザを閉じると消える)。切れる時間はサーバーで決める

## 要求の確かめ

- `/api/admin/` の下の API は、すべてサーバーでセッションと管理者であることを確かめる(ログインとログアウトを除く)。無ければ 401。画面の表示だけに頼らない(開発指針 0-4)
- データを変える要求(GET 以外。ログインも含む)は、Cookie に加えて `X-Genba-Admin: 1` のヘッダーが無ければ 403。別のサイトのページは、このヘッダーを付けて送れない(付けるとブラウザが事前の確認をし、本アプリは許可しない)ため、別のサイトからの送信を防げる。SameSite=Strict と二重の守り
- 現場の API は、今までどおりログインなしで使える

## マスタの管理(services/admin_masters.py)

| 対象 | できること |
| --- | --- |
| 設備 | 一覧(無効も含む)、追加、名前(日本語・ベトナム語)と並び順の変更、無効化・有効に戻す |
| 理由 | 一覧、追加、名前(日本語・ベトナム語)・区分・設備が必要か・理由の記入が必要か・付帯作業に使えるか・再開理由に使えるか・稼働率に含めるか・並び順の変更、無効化・有効に戻す |
| ライン | 一覧、名前と並び順の変更、無効化・有効に戻す(ラインは計画の同期で自動で登録する。名前を変えると、自動で付けた名前の扱いは外れる) |
| 作業者 | 一覧を見るだけ(既存アプリから読み込むため)。開発用の作業者だけは、legacy_app_dir が無いときに追加できる |

- 行は消さない。無効にした理由・設備は、現場の画面で選べなくなる。過去の記録は理由・設備の番号で持っていて、表示のときにマスタの名前を引くので、無効にしても表示は変わらない
- 変更はすべて audit_log に残す(誰が、いつ、どの表のどの行を、作った・変えた、変わった項目の変更前と変更後)。変わらなかった変更は残さない
- `PATCH` は送った項目だけを変える(送らなかった項目はそのまま)

## audit_log

| 列 | 中身 |
| --- | --- |
| changed_at、changed_by | いつ、誰が(作業者の番号。開発用コマンドからのときは空) |
| target_table、target_key | 何を(表の名前と、行の主キーを文字にしたもの) |
| action | create / update |
| before_json、after_json | 変わった項目の変更前と変更後(作ったときは変更前が空) |
| reason | 訂正の理由(次の回の実績の訂正で使う) |

## 画面(frontend/src/admin/)

- `/admin/login` でログイン。`/admin` の下は、左にメニュー(設備、理由、ライン、作業者、パスワードの変更、ログアウト)、右に内容
- 開いたときに `/api/admin/me` で確かめ、401 ならログイン画面に戻す。どの操作でも 401 が返ったら、ログイン画面に戻す(「ログインが切れました」を出す)
- 管理画面は日本語だけ(言語を切り替えない)。文言は `src/admin/messages.ts` にまとめ、vi.ts には足さない。画面のファイルに日本語を直接書かないテスト(`scripts/no-hardcoded-text.test.ts`)は管理画面にも当てる(辞書のファイルは除く)
- PC で使う前提(幅 1280px 以上)。タブレット向けの大きさにはしない
- ライン選択の画面の右下に、管理画面への小さなリンクを置く
