# 日報と区間の CSV の設計メモ

開発指針(docs/spec.md)の 7.2「日報と区間の CSV」と 11「稼働率などの集計」の、実装の判断の理由。

対象のコード:

| コード | 役割 |
| --- | --- |
| `backend/app/domain/intervals.py` | DBに触らない計算(稼働日の境目で分ける、上段・下段の区切りで分ける、時間(分)) |
| `backend/app/services/report_intervals.py` | 区間を作る(工程の記録と付帯作業を読み、計画・人・設備の名前を付ける) |
| `backend/app/services/report_csv.py` | 区間の CSV(見出し、BOM、CRLF、ファイル名) |
| `backend/app/services/daily_report.py` | 日報の値(行と棒、上段・下段、合計) |
| `backend/app/api/admin_reports.py` | 管理画面のAPI(管理者のログインが要る) |
| `frontend/src/admin/reports/` | 日報のページ(ReportsPage)、日報の形(DailyReportView)、計算(gantt.ts)、印刷の CSS(report.css) |

## 集計はアプリの中でしない(今は)

稼働率の定義が決まっていない(spec 11)。定義に関わらず使えるよう、アプリは「時間の区間」を漏れなく出すところまでにし、集計は CSV を Excel などで行う。日報は区間をそのまま並べたもので、合計は生産数とNG数だけ。

## 区間(services/report_intervals.py)

- 1件 = 取り消していない工程の記録、または付帯作業の記録(取り消した記録は出さない)
- **稼働日をまたぐ記録は、稼働日の境目(`schedule.day_start`)で分ける。** 夜勤の続きの片付け(7:50〜8:30)は、前の稼働日の 7:50〜8:15 と、その日の 8:15〜8:30 の2つになる。日ごとの集計で、時間を稼働日に正しく割り当てるため。元の開始・終了の列も残す(同じ記録だと分かるように)
- **生産数は、終了を含む区間にだけ付ける。** 分けた区間の両方に付けると、合計が2重になるため。生産数は区切りの終了で数えたもの、という考え方に合わせた
- **終了していない記録**: 終了の列は空、時間は出力した時刻(サーバーの時計)まで、「作業中」の列に印。終了していない記録が稼働日の境目をまたいでいれば、境目までの区間(終了の列は境目)と、今までの区間(終了の列は空)に分ける
- 時間は分で、小数1桁(秒の単位まで記録しているため)
- ロットNo.と品名は、計画のまとまり(キッティングNo.)のロットを「、」でつなげる(同じ品名は1つにまとめる)
- 「訂正あり」は、その記録に run_corrections の行があるか。「後から追加」は押し忘れの追加(added_later)
- 見出しに無い列を2つ足した: 「再開理由」(生産の2回目以降の区切りの再開理由)と「理由の記入」(付帯作業のその他トラブルの記入)。マシントラブルなどを、計画の中の停止と合間の付帯作業とで同じように集計できるようにするため
- 期間の外の稼働日の区間は捨てる(記録の一部だけが期間に入っていれば、その部分だけ出す)

## 区間の CSV

- BOM 付きの UTF-8、改行は CRLF。日本語の Excel は、BOM が無い UTF-8 を Shift_JIS として読んで文字化けするため。Shift_JIS にしないのは、ベトナム人の作業者の名前などで Shift_JIS に無い文字が出うるため
- 見出しは日本語。はい/いいえの列は「○」と空
- ファイル名に期間とラインを入れる(`intervals_2026-10-01_2026-10-31_S.csv`。すべてのラインは all)。日本語のファイル名にしないのは、Content-Disposition で文字化けしないようにするため
- 期間の上限は `[reports] max_days`(既定93日 = 3か月分)。全件を読んで並べるので、極端に長い期間で重くならないように
- 画面からは openapi-fetch で受け取り(`parseAs: "blob"`)、ブラウザに保存させる。401(ログイン切れ)と 409(期間の誤り)の理由を画面に出すため(リンクで開くと、エラーの JSON がそのまま開いてしまう)

## 日報(services/daily_report.py、frontend/src/admin/reports/)

- 区間はその稼働日のもの(CSV と同じ区間)。上段 = day_start から12時間、下段 = 残りの12時間。棒は段の境目でも分ける(`split_at`)。終了していない棒は今まで
- 行: キッティングNo.ごとに1行(最初の開始の順)と、付帯作業の1行(あれば最後)。上段と下段で行をそろえる(棒が無い段でも行を出す。見比べやすく、ページの分け方が上段と下段で同じになるため)
- 生産数の合計 = その稼働日の区間の生産数の合計(上の「終了を含む区間にだけ付ける」による)
- NG数の合計 = 日報に出る計画の、ロットと面ごとの最新のNG数の合計。NG数には時刻が無い(入力し直すと最新が有効)ため、稼働日には分けられない。日をまたぐ計画は、それぞれの日に数える(仮置き。spec 11)
- **色だけで区別しない**: 工程の棒の中に略称(段取・N1・生産・初品・X線・片付)、凡例を付ける。付帯作業は短いことが多く、棒の中では理由が切れてしまうので、理由は棒の下に出す。作業中は斜線と点線の枠
- 工程の色は現場の画面(`field/line/steps.ts` の STEP_COLORS)と同じ
- **印刷**: `@page { size: A4 landscape; margin: 0 }` とし、余白はページ(`.report-sheet`)の中の padding(10mm)で取る。ブラウザごとの余白の既定に左右されず、画面と印刷で同じ形になるため。印刷ではメニューと操作の欄を隠す。棒の色を印刷するため `print-color-adjust: exact`
- **ページ分け**: 1ページ9行(A4 横向きの高さに、上段と下段の両方が収まる数)。行が多いときは次のページに続け、見出しと凡例を繰り返す(`paginate`)。ページの区切りは CSS の `break-after: page`
- 画面で見るときも、同じ大きさ(297mm × 210mm)のページを並べる(印刷したときの形を、そのまま確かめられるように)。管理画面の幅に入らないときは横にスクロールする

## 画面の確認(Playwright。e2e/reports.spec.ts)

- 記録は「押し忘れの追加」の API で過去の時刻に入れる(サーバーの時計は 10/21 10:00 から進むので、ボタンで記録すると長さが数秒になる)。screens.spec.ts が使う計画(0722、0800 など)と、ラインの今の担当者には触れない(記録した人は worker_id で指定する)
- ⑳ 稼働日 10/21 の日報の画面、㉑ 稼働日 10/20 を印刷の形(`emulateMedia({ media: "print" })`)にしたスクリーンショットと、`page.pdf` の PDF(A4 横向き)
