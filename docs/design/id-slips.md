# 識別票4種類の印刷(AD-20)

生産を始める前に、現場画面で計画を選び、識別票を印刷する。印刷はブラウザの印刷機能(`window.print` と印刷用 CSS)。プリンターは白黒、用紙は A6(白)。記録は読むだけで、変えない。

## 種類と使うとき

| 種類 | 名前 | 用紙 | 単位 | 初期値でチェックが入る計画 |
|---|---|---|---|---|
| 1 | 基板製品ロット現品票 | A6縦 | ロットごと | 2回目(面2) |
| 2 | バーコード印字 完了 | A6横 | ロットごと | 1回目(面1) |
| 3 | 1回目完了済み | A6横 | ロットごと | 1回目(面1) |
| 4 | バーコード照合用 | A6縦 | キッティングNo.ごと(1枚に全ロット) | 両方 |

初期値以外もチェックを入れれば印刷できる。様式は [forms/id-1-lot-slip.html](forms/id-1-lot-slip.html)、[id-2](forms/id-2-barcode-printed.html)、[id-3](forms/id-3-side1-done.html)、[id-4](forms/id-4-barcode-check.html)(ユーザーが用意したもの。中身は変えず、アプリからは読み込まない)。

## 画面

- ライン画面で計画を選ぶと、右のパネルに「識別票」のボタン。**表示範囲(48時間)の中で、取り消されていない計画**だけに出す(画面側の判定。直接 URL を開けば表示範囲の外でも開けるが、取り消した計画はサーバーが断る = 409)
- `/field/print/id-slips/:kittingNo`。操作バー(印刷に出ない)で、種類(4つのチェック)とロット(ロットごとの種類のとき。初期値は全ロット)を選ぶ。**1枚の識別票 = A6 の1ページ**で、ロットごとの種類(1・2・3)は選んだロットの数だけページを出し(同じロットの同じ種類を2ページ以上出さない)、4つ目はキッティングNo.で1ページ。**枚数の欄はない**(AD-23 で外した。枚数はブラウザの印刷の画面で決める)。種類ごとの「この種類を印刷」で、**その種類のページだけ**を印刷に出して `window.print`
- @page は名前付き(`slip-p`: 105mm × 148mm、`slip-l`: 148mm × 105mm、余白 3mm)。生産記録票(`record`)と日報(無名)とぶつからない
- API は読み取りだけ: `GET /api/id-slips/{kitting_no}`(IP 制限のみ。現場画面と同じ)

## 欄と元データ

| 種類 | 欄 | 元データ |
|---|---|---|
| 共通 | File № | 計画のファイルNo.。数字だけなら先頭の0を外す(0722 → 722)。英字が混じる値(S010)はそのまま |
| 共通 | 製品名 / ロットNo. | 計画の製品名 / ロットNo. |
| 1・2・3 | 下のバーコード | 「SUF-」+ 保存されている4桁のファイルNo.(SUF-0722)。Code 39、下に文字 |
| 1 | 製品名の欄のバーコード | 先頭の0を外したファイルNo.。Code 39、文字なし |
| 1 | ロットNo.の欄のバーコード | ロットNo.。Code 39、文字なし |
| 1 | 数量「分割数量 / LOT総数」 | LOT総数 = 発注数 C(plans.order_qty。無ければ空)。分割数量は空欄 |
| 1 | LOT数、分割総数、後工程、メモ | 空欄(手書き、押印) |
| 4 | キッティングNo. | その計画のキッティングNo.。バーコード(Code 39、文字なし) |
| 4 | Lot | そのキッティングNo.の全ロット(「, 」区切り。ロットの途中では折り返さない)。収まらなければ文字を縮める(最小 8px) |

**ファイルNo.の保存の形**(実データの調査): 既存アプリの `setup_file_no` は常に4文字の文字列(2,482行すべて)。数字だけの値は0で埋めた4桁(`0002`、`0722`。2,408行)で、英字が混じる値は大文字のまま(`S010`、`T207` など)。本アプリは正規化して(`normalize_setup_file_no`)そのまま保存する。そのため、表示は「数字だけなら先頭の0を外す」、バーコードの SUF- は保存されている4桁のまま。

## 様式の直し(4種類共通)

- 外枠は青から黒に。ポルトガル語(PRODUTO、LOTE、PLACAS PRONTAS O LADO 1)は外す
- 共通の見出し(4種類で同じ): `File №` / `製品名 / Tên sản phẩm` / `ロットNo. / Số lô` / `キッティングNo. / Số danh sách kitting`
- そのほかの見出しは日本語の下にベトナム語を小さい字で足す(下の訳の表)。表題「バーコード印字 完了 / Hoàn tất in mã vạch」「1回目完了済み / Lần đầu tiên hoàn thành」と「Format 2018/1/18」は様式のまま
- A6 いっぱいでは端が印刷できないので、余白 3mm を取り、様式の大きさのまま描いたものを **0.94 倍**に縮める(1〜3)
- 1つ目(現場票)は、下の空白を埋めるため、**「部品後付」の行(後工程のチェック欄の、印を押す行。38px)と「スクラップ」の行(メモの印の欄。44px)だけを、同じ割合(`--slip1-grow` = 2.34 倍)で縦に広げた**(AD-25)。ほかの行の高さ・文字・バーコードは変えず、最下部(用紙色、File №、SUF のバーコード)は用紙の下に残す。空白は、本体の表と最下部の表のあいだの隙間(`justify-content: space-between`)で、広げる前は約 28.8mm(印刷の大きさ)、広げたあとは約 1.5mm(Playwright で測る。3mm 以下が条件)。行の高さを変えたら、`--slip1-grow` を測り直す
- 4つ目は A6縦(余白を除いた 99mm × 142mm)いっぱいに、行の高さの比率(28:60:40:36:70)を保って広げ、文字も大きくする。様式の列(17/33/17/33)は、見出しにベトナム語を足したぶん広げた(24/18/18/40。ロットが並ぶ欄を広く)。「Lot」は様式では File № の隣の欄のまま
- 様式の2は見出しだけで値の欄が空だったので、3と同じく値を大きく出す
- フォントは Arial を先にする(ベトナム語の声調記号が Meiryo では崩れるため)

## バーコード

- JsBarcode(MIT。npm で入れてアプリに含める。[dependencies.md](dependencies.md))で符号にし、SVG はアプリ側で mm の大きさで描く(`print/idslips/`)。CDN は使わない
- 細いバーの幅は印刷で **0.25mm 以上**(0.94 倍に縮めたあとの大きさ)。枠に収まる範囲で、1の製品名・ロット・下は最大 0.35〜0.4mm、4は最大 0.5mm。ロットNo.が長くて 0.25mm でも枠に収まらないときは、枠(1のバーコードの欄)を広げる
- Code 39 で表せない文字(英小文字、日本語など)が値にあるときは、バーコードを描かず値の文字だけを出し、操作バーに警告を出す。大文字には直さない
- 読み取りの確認はユーザーが実機で行う(プリンターの解像度で 0.25mm が何ドットになるかによる)

## 1ページにならなかった原因と直し(AD-23)

症状: 印刷すると自動で2ページになり、同じ識別票が2枚出る。原因は2つあった。

1. **横向き(種類2・3)の白紙の2ページ目**(✔ Playwright で再現。1ロットで PDF が2ページ、2ページ目は白紙): 縮める前の大きさ(105×148mm)の箱 `.slip-scale` を、枠の中の流れに置いていた。縮める前の高さは A6 横の余白を除いた領域(99mm)より大きく、枠(`overflow: hidden`、98.8mm)からはみ出した分が次のページとして組まれた(縦向きは 142mm の領域に収まるので出なかった)。**直し**: `.slip-scale` を枠の中に絶対配置して、ページの組みに加えない。
2. **種類が重なって出る**(✔ Playwright で再現。△ 実機の Chrome の印刷の画面では未確認): 「この種類を印刷」で押した種類だけを出す印を、`afterprint` で外していた。Chrome の印刷の画面は、用紙や余白を変えるたびに組み直し、そのたびに `afterprint` が飛ぶと見ている(PDF を作ると飛ぶことは Playwright で確認)。外れると、チェックの入った全部の種類(面1の計画では 2・3・4。2 と 3 はどちらも A6 横の、ほぼ同じ識別票)が出て、同じ識別票が2ページになる。**直し**: `afterprint` で戻さず、種類やロットを選び直すまで押した種類を覚える。ボタンを押さずに Ctrl+P を押したときは、チェックの入った種類のすべてが出る。

あわせて、`.slip-frame` に `break-inside: avoid` を足した。

## 確かめ方

- 自動: Playwright で、種類ごとに、ロット1つで PDF が1ページ、ロット3つで3ページ(4つ目は1ページ)、印刷の画面の組み直し(`afterprint`)のあとも1ページ(`e2e/zz-id-slips.spec.ts` の㊺・㊺b)。
- **実機(Chrome と Edge。人が行う。未実施)**: 識別票のページで種類を1つ選んで「この種類を印刷」→ 印刷の画面で、用紙サイズ **A6**、余白 **既定**、倍率 **100%**、ヘッダーとフッター **オフ**、(PDF保存でなく)白黒のプリンターを選ぶ → **プレビューが1ページ(ロットが1つのとき)**になることを確かめる。用紙サイズを変える、余白を変えるなどの操作をしても、ページ数と中身が変わらないこと。ロットを3つ選べば3ページ。部数は印刷の画面の「部数」で決める。

Playwright `e2e/zz-day-select.spec.ts`(ラインD。現場票の PDF が1ページで、空きが 3mm 以下)、pytest(`tests/records/test_id_slips.py`)、vitest(`print/idslips/*.test.ts`)、Playwright(`e2e/zz-id-slips.spec.ts`。種類ごとの A6 の大きさと1枚1ページ、ロット1つで1ページ・3つで3ページ、4つ目のロット10個で1ページ、細いバーの幅)。実機の手順は上。
