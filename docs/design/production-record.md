# 生産記録票(実装工程。現場の画面から印刷)の設計メモ

AD-18(2026-11-03)。計画ごとの「実装工程 生産記録票」(A4縦、日本語とベトナム語の併記)を、現場のタブレットまたはPCのブラウザから印刷する。
印刷はブラウザの印刷機能(`window.print` と印刷用 CSS)。PDF の生成やサーバー側の印刷はしない。対象のコードは
`backend/app/services/production_record*.py`、`backend/app/api/production_records.py`、`frontend/src/print/`。

## 様式(見た目の基準)

ユーザーが用意した様式(実装工程 生産記録票、改正 2025/02/25 Ver.02)の HTML を [forms/production-record-ver02.html](forms/production-record-ver02.html) にそのまま保存してある。**見た目の基準として残すだけで、アプリからは読み込まない。** 列の幅(18/27/15/3/15/11/11%)、行の高さ(基本は様式の値)、外枠の太線(2px)と中の細線(1px)、文字の大きさ(11px、ベトナム語の小さい字は 8.5px)、日本語とベトナム語の併記は様式に合わせた(`frontend/src/print/record.css`)。行を足す所(ロット、生産、同じ工程の複数の記録)だけ、同じ見た目で増やす。様式から変えたのは次の3点だけ:

1. 1回目の明細の2列目の見出しを、2回目と同じ「作業者名 / TÊN NGƯỜI THAO TÁC」にした
2. 1回目の作業名にも、2回目と同じベトナム語の小さい字を付けた
3. 様式の「生産/X線検査」の行を、「生産」と「X線検査」の別々の行に分けた(生産の基本の3行 + X線検査の1行が、初品確認の番号 1〜4 の4行に並ぶ。それより多い行は初品確認の2列が灰色)

このほか、様式にない表示を2つ足した: ライン欄の枠の下にキッティングNo.(小さい字)と、面が未完了のときの「未完了」。様式にあった A/B/C の説明は、様式に無いので入れていない(数量は「A / B / C」の形のまま)。ベトナム語の綴りと言い回し(「N° DA PLACA」などを含む)は様式のまま。文字は Arial → Meiryo の順で指定した(Meiryo にはベトナム語の声調記号の字が無く、様式のままだと記号がずれて見えたため)。

## 原紙(Excel)に寄せた点(AD-18c)

ユーザーが使っている原紙の Excel に合わせて、様式の HTML から次を変えた。原紙そのものはリポジトリに入れない(外部への参照が入っているため)。ベトナム語の併記、データの組み立て、API の形、一覧、組み合わせは変えていない。

| 点 | 様式の HTML | 今 |
|---|---|---|
| 余白 | 8mm | 上下 5mm、左右 3mm(`@page record { margin: 5mm 3mm }`)。表は左右の中央 |
| ページの使い方 | 行が低く、ページの下の約2割が空く | 行の高さを mm で決め、手書きの場所を広く取る。基本の場合(ロット6行まで、各面で生産3行 + X線検査1行)で、ページの下の空きは約 10mm |
| ライン欄 | 見出しと値の2段 | 「1回目」「2回目」の右に、ラインの記号の枠(24px・太字。印を押す場所なので周りに余白)、その右に見出し「ライン / ĐÓNG DẤU CHUYỀN」。キッティングNo. と「未完了」は枠の中の下に小さい字(8.5px)。半田・ボンド・基板番号(1回目だけ)は、見出しの下に手で書く行。2回目は基板番号が無い分、ボンドの欄を広げる |
| 明細の列 | 18/27/15/3/15/11/11% | 作業 16 / 作業者名 27 / 開始 13 / ～ 3 / 終了 15 / 生産台数 10 / 初品確認の番号 3 / 初品確認の記入欄 13% |
| 生産台数 | 面ごとに1つ(良品の累計。4行にまたがる) | **生産の行ごと**に、その区切りの良品の台数(`StepRowOut.good_qty`)。X線検査・段取り・片付けの行は灰色。合計の欄は無い(原紙に無い)。記録の無い生産の行は空欄(手書き用)。生産の行が4行より多くても、行ごとに欄が付く |

| 数量 A の実績 | なし | A の面の計画が完了していて、ロットの実績の台数が A と違うとき、A に取消線を引き、すぐ右に実績を太字で出す(例: ~~300~~ **298** / 600 / 1000)。色は使わない(白黒で印刷するため) |

行の高さの目安(基本の場合): ライン欄の段 約 16mm、明細の見出し 5mm、作業の行 9.5mm(段取り、マスターチェック、生産×3、X線検査、片付けの7行)、トラブル欄 約 17mm(見出し 4.5mm + 枠 12mm)、表と表の間 2mm。10mm の目安から、作業の行とトラブル欄を少し詰めたのは、見出しの折り返しなどで高さが増え、10mm では A4 の 287mm を超えたため。

### 数量 A の実績の読み方

実績の台数は、**実績の書き出し(13列の CSV)と同じ割り振り**(`actuals_rows.lot_actuals`。別の計算は作らない)。両面の組は面2の行の値、面2が無いロットは面1の値。A の面の計画が完了していないとき、実績が無いときは、これまでどおり A だけを出す。管理者が実績の画面で直した割り振りは、書き出しの操作のときだけ送られる値で、**サーバーには保存されない**ため、記録票には反映できない(記録票は、記録から割り振った値を出す)。B(この計画を含めた累計)は A を含んだ値なので、実績が A と違うと B がずれる。B は変えていない。

## 1枚の単位と組み合わせ

- **1枚 = 両面の1組**(1回目 = 面1のキッティングNo.、2回目 = 面2のキッティングNo.)
- 組み合わせは、実績の書き出しと同じ読み方(AD-19。`side_link_store.current_links` の明示の紐づけ、無ければキー H)をそのまま使う(`production_record_pair.py`)。印刷のためだけの規則は持たない
- 1回目と2回目でラインが違う組(1回目 Sライン、2回目 Uライン)も、紐づいていれば1枚にまとまる。ラインは面ごとに、その面の計画のラインを出す
- 面1とつながっていない面2は、2回目だけを埋めて出す。印刷のページの上(印刷には出ない所)に「1回目と紐づける」を出し、その面2を選んだライン画面(`/field/lines/<ライン>?kitting_no=<キッティングNo.>`。AD-19 の紐づけの欄)へ進める
- 面2の無い面1(片面製品など)は、2回目を空欄で出す
- 相手の計画が取り消されていれば、つながっていない扱い(面1なら2回目が空欄、面2なら「1回目と紐づける」)

## 印刷できる計画と画面

- 対象は片付けが終わった計画(完了)。**両面の組では、どちらかの面が完了していれば印刷でき、未完了の面は記録のある所まで埋める**(その面の見出しに「未完了」を出す)。どちらも未完了なら 409、取り消された計画は 404
- 一覧(`GET /api/production-records`): 1組で1行。どちらかの面の完了日が過去31日以内の組を、完了日の新しい順に出す(現場の画面の表示範囲の48時間とは別)。ライン(どちらかの面)、キッティングNo.(どちらかの面。部分一致)、ロットNo.(部分一致)で絞り込める。取り消しの印がある計画は出さない
- 一覧から選ぶと `/field/print/production-record/<キッティングNo.>`(どちらの面のキッティングNo.でもよい)を開き、「印刷」で `window.print` を呼ぶ。**片付けの終了時に自動では開かない**
- 現場画面のボタン「生産記録票」は、ライン画面の上部とライン選択の画面にある
- 認証は現場の画面と同じ(IP 制限が効く)。新しい API は読み取りだけで、実績の記録と紐づけは変えない

## 数量 A・B・C(調査の結果)

既存アプリの月次DB `kitting_plan_items` の列を、計画の取り込みがすでに読んでいる(`integration/legacy/plans.py`)。取り込みの追加は要らなかった。

| 記号 | 既存アプリの列 | 本アプリの列 |
|---|---|---|
| A | `planned_qty` | `plans.planned_qty` |
| B | `cumulative_qty_external` | `plans.cumulative_qty` |
| C | `order_qty` | `plans.order_qty` |

NANJYOU-H の月次DB(`C:/work/inventory/dist/db/202610/inventory.db`、有効な計画 2482 行)で確かめた(読み取りのみ)。B はすべての行で A 以上、C 以下の行が大半で、同じロットの計画が複数あるときは累計が積み上がる(例: 発注 600 のロットで、1つ目 300 / 累計 300、2つ目 300 / 累計 600)ため、「この計画を含めたこれまでの累計」と読める。C は同じロットの行で同じ値。キー H でつながる面1・面2のロット 847 件のうち、A・B が違うのは 1 件(B だけ。面1 1800、面2 1200。A と C は同じ)で、C が違うロットは無い。違うときは**面1の計画の値**を出し(面1にそのロットが無ければ面2)、違うロットは API の `qty_differs` で分かる(確認用のデータでは、すべて同じ値)。

## 付帯作業(トラブル)の範囲

その面の**最初の工程の開始から、片付けの終了まで**に、**その面の計画のライン**で起きた付帯作業(取り消していないもの)。範囲と重なるものを出す(範囲の前に始まって範囲の中で終わるものも含める)。片付けが終わっていない面は、今まで。1回目と2回目でラインが違えば、それぞれのラインの付帯作業を出す。

## 印刷の見た目

- 用紙は A4 縦、余白 上下 5mm・左右 3mm(原紙に合わせた)。日報(A4 横。`@page { margin: 0 }`)の `@page` とぶつからないよう、**名前付きのページ**(`@page record { size: A4 portrait; margin: 5mm 3mm }`、`.record-sheet { page: record }`)にしている
- 行が多いときは1枚に収まるよう、行の高さと文字を縮める。描いたあとに高さを測り(`RecordPage.tsx`)、1080px(= 287mm)を超えたら、**行の高さから先に**縮める: 通常 → dense(高さ×0.8)→ tight(高さ×0.65、文字 10px)→ tiny(高さ×0.5、文字 9px、ベトナム語 8px)と進める(`recordLayout.ts`)。文字は最小 8px。基本の場合は縮めない(Playwright で確かめる)。10ロット、各面の生産の区切り6つ、付帯作業5件で、A4縦1ページに収まる(Playwright で確かめる)
- 様式の文言は**日本語とベトナム語の併記で固定**し(文言は様式のとおり。ベトナム語が無い欄は日本語だけ)、画面の言語の切り替えには従わない。文言は `frontend/src/print/recordTexts.ts` にまとめ、コンポーネントに直接書かない(i18n の `ja.ts` / `vi.ts` / `admin/messages.ts` とは別のファイル。紙の様式は1つで、画面の言語に合わせて変える必要がないため。詳細: [i18n.md](i18n.md))。画面側の文言(一覧、ボタン、「1回目と紐づける」など)は `ja.ts` と `vi.ts` の `record.*`

## ChromeとEdgeでの見た目の確かめ方(Ctrl+P)

タブレットでの確認は担当者が行う。PC では次の手順で確かめる。

1. 確認用のデータ(`python -m app.cli demo-seed --line R --date YYYY-MM-DD --record-samples`)を入れ、記録を入れて片付けまで終える(Playwright の `e2e/zz-production-record.spec.ts` が同じ状態を作る)
2. ライン画面の「生産記録票」→ 一覧から組を選び、印刷用のページを開く
3. **Ctrl+P**(または「印刷」ボタン)で印刷の画面を開く
4. 次を確かめる:
   - 用紙: **A4**、向き: **縦**(ページの指定で自動的に縦になる。横になっていたら、その設定を確かめる)
   - 余白: **既定**(上下 5mm・左右 3mm はページの指定)。倍率: **100%**(「用紙に合わせる」にしない)
   - 「ヘッダーとフッター」は**オフ**(日付や URL が紙に入らない)
   - 「背景のグラフィック」は、見出しの薄い灰色を出すならオン(オフでも、罫線と文字は印刷される)
   - プレビューが **1ページ**で、操作バー(印刷・一覧へ戻る・「1回目と紐づける」)が出ていないこと
   - ロットの行、工程の行、トラブルの行が切れていないこと、文字が読めること(最小 8px)
5. Chrome と Edge の両方で同じ見た目になることを確かめる。違う場合は、倍率と用紙の設定を先に疑う
6. 「PDFに保存」で保存して、見た目を残してもよい(アプリはPDFを作らない。ブラウザの機能)

## 画面の確認(Playwright。e2e/zz-production-record.spec.ts)

ラインRの確認用データ(`--record-samples`)に記録を入れ、印刷のメディア(`page.emulateMedia({ media: "print" })`)で、10ロットの両面の組が A4縦1ページに収まること(`page.pdf` のページ数と、用紙の高さ)、操作バーが印刷に出ないこと、文字が 8px 以上であることを確かめる。基本の場合(S/U の組)は、行を縮めない(`record-normal`)、ページの下の空きが 15mm 以下、作業の行の高さが約 9.5mm であることも確かめる。A と実績が違うロット(10ロットの組)の取消線は、`41-record-actual-differs.png` に撮る。あわせて、片面だけ、「1回目 Sライン、2回目 Uライン」(AD-19 で紐づけたあと1枚)、面1とつながっていない面2(「1回目と紐づける」から紐づけの欄へ進める)のスクリーンショットを `test-results/screens/` に撮る。
