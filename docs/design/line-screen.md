# ライン画面(現場画面)の設計メモ

開発指針(docs/spec.md)の 7.1 の実装の判断の理由。対象のコードは `frontend/src/field/line/` と `frontend/src/shared/`。

## 部品の分け方

| ファイル | 役割 |
| --- | --- |
| `LineScreen.tsx` | 全体の組み立て(選んでいる計画、出すダイアログ) |
| `TopBar.tsx` / `SideMenu.tsx` | 上部(ライン名・稼働率・ラインの進捗率・今の担当者)と左のメニュー |
| `Timetable.tsx` | 中央のタイムテーブル(計画の枠・実績・付帯作業の3列) |
| `StepPanel.tsx` / `LineEventPanel.tsx` | 右のパネル(工程のボタン・NG数・備考)と付帯作業 |
| `LineDialogs.tsx`、`dialogs/`、`OperatorPicker.tsx` | ダイアログ(テンキー、再開理由、確認、文字入力、付帯作業の設備・理由、担当者の交代) |
| `useBoard.ts` / `useLineActions.ts` / `useNow.ts` | board の読み直し、APIの呼び出し、今の時刻 |
| `timeScale.ts` / `steps.ts` | 表示から分けた計算(時刻と位置の変換、重なりの列、工程の状態)。vitest でテストする |

## APIクライアント

- 型は FastAPI の OpenAPI から `npm run gen:api` で生成する(`src/api/schema.ts`。手で編集しない)。バックエンドの venv の Python で `python -m app.openapi_export` を動かして OpenAPI を書き出し、openapi-typescript で型にする
- 呼び出しは openapi-fetch(`src/shared/api.ts`)。手書きの fetch は使わない。APIの型が変わったら生成し直し、型エラーで気づけるようにする

## ボタン操作の送り方(src/shared/send.ts、useOperation.ts)

- request_id は操作ごとに1つ作り、成功するまで、同じ操作・同じ内容なら同じ値で送る(内容が変われば作り直す。同じ request_id で内容の違う操作を送ると 409 になるため)
- UUID v4 は `crypto.getRandomValues` から作る。`crypto.randomUUID` は安全な接続(HTTPS)でしか使えず、HTTP の社内LANでは使えないため
- 送信中は、そのボタンを押せない状態にする
- 通信の失敗と 503 は、同じ request_id で自動で1回だけ送り直す。それでも失敗したら理由を画面に出す
- 409 と 404 は送り直さず、応答の detail をそのまま出す(サーバーの文は画面にそのまま出せる日本語にしてある)
- 成功したら、すぐに board を読み直す。ダイアログは送る前に閉じ、結果はお知らせと board で分かるようにする

## 画面の更新

- board は5秒ごとに読み直す。画面が非表示のあいだ(visibilitychange)は止め、表示に戻ったらすぐ読み直す
- 古い応答があとから届いても、新しい応答を上書きしないようにする
- 今の時刻の線と経過時間は、端末の時計で10秒ごとに更新する(記録の時刻はサーバーが付ける)

## タイムテーブル

- 縦軸はその日の 0:00〜24:00(日本時間)。1時間 = 90px。開いたときは今の時刻のあたりまで自動でスクロールし、今の時刻に線を引く
- 時刻と位置の変換は端末の時間帯によらず日本時間で計算する(`timeScale.ts`)
- 終了していない記録は、今まで伸ばす。前の日から続くもの・次の日まで続くものは、その日の範囲で切る
- 重なる計画・記録は横に並べる(空いた列は使い回す)。短い記録も工程名が読めるよう、最低の高さを付ける
- 工程ごとの色に加えて、工程名と「作業中」の文字も出す(色だけで区別しない)

## タブレット向けの決まり

- 押す部分は高さ 56px 以上、本文 16px 以上、ボタン 18px 以上。ホバーに頼る表示はしない
- 画面の幅 1024〜1366px(横向き)で横にはみ出さない(Playwright で確かめる)
- 背景を押してもダイアログは閉じない(押し間違いを防ぐ)。閉じるのは「やめる」だけ
- 担当者が未設定なら、案内を出す(ボタンを押すとサーバーが 409 を返し、その理由を出す)

## 画面の確認(Playwright)

- `npm run e2e` で、確認用のデータ(`python -m app.cli demo-seed`)を入れたDBを毎回作り、ビルドした画面をバックエンドが配信する形で操作する(`e2e/serve.mjs`)
- 画面の大きさは 1280×800(タブレットの横向き)。スクリーンショットは `frontend/test-results/screens/`(Git の対象外)
