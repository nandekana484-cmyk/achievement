# K社製品ロット管理票(AD-27)

生産の前に、「K社製品ロット管理票」(A4縦。1ロットに1枚)を印刷する。表の中身(工程の行と作業要領)と管理Noはファイルno.ごとに違うので、**管理画面でファイルNo.ごとに登録**し、印刷のときにその内容で表を作る。実績の列(作業者/日付、合格/完了数、NG数、NG理由)は今は手書き。印刷は識別票の印刷のページの**5つ目の種類**(詳細: [id-slips.md](id-slips.md))。

様式: [forms/control-sheet-k.html](forms/control-sheet-k.html)(ユーザーが用意したもの。中身は変えず、アプリからは読み込まない)。見た目(表の分け方、列の幅、行の高さの比率、線、文字の大きさ、太字、斜線、作業要領の欄の罫線、印の枠)は様式に合わせた。様式の表の中身(SMT-1、Side B、X線検査、検査数 5 枚など)は例で、印刷では下の登録内容に差し替える。

## 印刷する欄と元データ

| 欄 | 元データ |
|---|---|
| セットアップファイルNo. | 計画のファイルNo.(表示は識別票と同じ規則。数字だけなら先頭の0を外す = `display_file_no`) |
| 管理No | ファイルNo.ごとの内容の管理No。未登録なら空欄 |
| 製品名 | 計画の製品名 |
| ロットNo.(大きい枠) | 計画のロットNo.(枠に収まる大きさに縮める。最小 8px) |
| ロットNo.の右の小さい枠、分割最終記号の丸 | 空欄(手書き。分割のロジックは後日) |
| 当ロット数「A / C」 | A = その計画での生産数(`plans.planned_qty`)、C = 発注数(`plans.order_qty`。無ければ空)。印刷するロットの計画の値(API の `lots[].planned_qty` / `order_qty`) |
| 工程の行 | ファイルNo.ごとの内容。行の番号は1から振る。**登録した行が8行より少ないときは、8行になるまで下に空の行を足す**(足した行はライン名の欄に斜線。様式の4〜8の行と同じ。足すのはサーバー = `print_data`。登録した空の行は、登録した設定のまま。**未登録のときの空の8行だけは、斜線なし**) |
| 各行の作業者/日付、合格/完了数、NG数、NG理由 | 空欄(手書き) |
| 「組立工程へ」の行 | 様式のまま、表の最後 |
| 工程抜け確認印、メモ・処置欄、作成・確認・承認 | 空欄 |

固定(様式のまま): 表題「K社製品ロット管理票」、「MP」、「WHITE PAPER(A4)」。ポルトガル語は外し、日本語の下にベトナム語を小さい字で付けた(下の訳)。印刷は白黒。

## ファイルNo.ごとの内容(管理画面「管理表の内容」)

- **管理者だけが編集できる**(`/api/admin/control-sheets`。ログインと `X-Genba-Admin` が要る。`tests/admin/test_admin_routes_guard.py` が確かめる)。画面は `frontend/src/admin/controlsheets/`、文言は `admin/messagesControlSheet.ts`(`messages.ts` は300行を超えているので足さない)
- キーは `plans.file_no`(既存アプリの setup_file_no と同じ値)。保存されている値のまま(`0722`)。20文字まで
- 登録するもの
  - 管理No(文字。50文字まで)
  - 工程の行(何行でも。上限 100。追加・この下に追加・削除・上へ/下へ)。1行に
    - 工程名(日本語。**空でもよい** = 手で書く行)と、工程名のベトナム語(任意)。工程名も作業要領も空の行を登録できる(区分、ライン名の欄を使うか、の設定は空の行にも持つ)。管理画面のボタンは「空の行を足す」
    - 区分(社内 / 社外 / なし)
    - 作業要領・注意点(複数行。Side A/B の内容や、X線の検査数などもここに書く)
    - ライン名の欄を使うか(使わない行は、ライン名の欄に斜線)
    - 将来の自動入力のための対応(なし / 1回目 / 2回目 / X線検査。**今は印刷に使わない**)
- 別のファイルNo.の内容をコピーして新しく作れる(`POST /{file_no}/copy`)。コピーするのは工程の行だけ(管理No はファイルNo.ごとに違うので空)。すでに登録済みのファイルNo.には上書きしない(409)
- 一覧: 登録済みのファイルNo.(版、行数、最後に直した人と日時)と、**今の(取り消されていない)計画にあって未登録のファイルNo.**(製品名つき。未登録を先に出し、色を付ける)
- **履歴**: 保存のたびに表 `control_sheet_versions`(マイグレーション 0021)に版を1つ足す。更新も物理削除もしない。最後の版が今の内容。履歴から前の版を読み込める(画面に読み込み、保存すると新しい版になる)。内容が同じなら版は足さない。audit_log に `control_sheet_save` / `control_sheet_copy`(変更前と変更後)
- 工程の行は JSON(`rows_json`)で持つ。行を別の表にしないのは、版ごとに丸ごと保存して履歴を見るため

## 印刷のページ

- 識別票のページの5つ目「管理表(A4縦)」。単位はロットごと(1ロットで1ページ)。初期値でチェックが入るのは**2回目(面2)の計画**。面2が無い計画(片面製品)は1回目でも、チェックを入れれば印刷できる(識別票の1つ目と同じ)
- 種類ごとに分けて印刷(`この種類を印刷`)。名前付きの @page `sheet-k`(A4縦、余白 8mm)。枠は 194mm × 280mm
- **未登録**のとき、工程の行は空の8行(番号だけ。ライン名の欄は斜線なし)で印刷し、操作バーに「このファイルNo.の管理表の内容は未登録です」と出す(API は `control_sheet.registered = false`。上の規則とは違い、足す行に斜線を引かない = `use_line` が True)
- **1ページに収める**: 生産記録票と同じく、描いてから測る(`ControlSheet.tsx`)。高さが `MAX_HEIGHT_PX`(1056px)を超えたら、詰め具合を1段階ずつ上げて描き直す(`controlsheet.css` の `.sk-d0`〜`.sk-d7`)。**行の高さを先に(d1〜d3: 48 → 40 → 32 → 24px)、文字をあとから(d4〜d6: 9 → 8.5 → 8px。最小 8px)、最後に上の欄と下の欄の余白(d7)を縮める**。20行・作業要領が各行3行でも、d7 で 278.6mm に収まる(Playwright)。それでも収まらないとき(作業要領が各行3行なら 22 行以上)は、**操作バーに「行が多くて1ページに収まりません(N行)。管理画面で行か作業要領を減らしてください」(印刷はできるが、管理表は2ページ目に分かれる、とも書く)と出し**、枠を伸ばして2ページ目に続ける(`.sk[data-overflow]`。1ページ目の下で切らない)。判定は一番詰めた段階で、まだ上限を超えること(`overflowsAtLimit`)。管理画面の編集では、**20行を超えたら「1ページに収まらないことがあります」と出す**(保存は止めない。`PAGE_FIT_ROWS`)
- **作業要領の欄の罫線**は、文字が無い部分にも引く(手で書き足せるように)。罫線の間隔は文字の行の高さ(`--lh`)と同じで、文字は罫線に乗る
- 文言は `print/idslips/controlSheetTexts.ts`(日本語とベトナム語の併記で固定。画面の言語に従わない)

## 将来の自動入力の考え方

実績の列(作業者/日付、合格/完了数、NG数)は、工程の行の「対応」(1回目 / 2回目 / X線検査)で、記録(`run_events`、NG、完了)から埋める想定。**今は手書きで、対応は保存するだけ**(印刷に使わない)。実績を入れるときは、対応のある行だけ埋め、対応なしの行は手書きのままにする。分割最終記号・ロットNo.の右の小さい枠(分割のロジック)も後日。

## Excel からの一括取り込み(AD-28)

ファイルNo.が約1000種類あるので、管理表の内容を Excel のブックから一括で取り込める(管理画面「管理表の内容」の「Excelから取り込む」。管理者だけ)。Excel の中身は社内の情報なので、**サーバーの中だけで読み、ブックは残さない**(読み終えたら捨てる)。読んだ中身はログに書かない(件数とエラーの理由だけ)。ユーザーの Excel はリポジトリに入れない。テストのブックはコードで作る(`backend/tests/book_helpers.py`)。

### ブックの形

- 1つのブックに、ファイルNo.ごとに1シート。シートの名前がファイルNo.。各シートは管理票の印刷の形そのまま
- 位置の例(Excel の表記): 管理No の見出し L1 と値 L2(L2:N2 結合)、セットアップファイル№ の見出し A3 と値 A4(A4:B5 結合)、製品名 C6(取り込みには使わない。製品名は計画から出す)、表の見出し 15行目(A「NO」、B「工程名」、C「作業要領･注意点」、H「ライン名」)、16行目はポルトガル語の見出し、工程の行は17行目から(A列の番号は縦に結合)、表の終わりは C列の「組立工程へ」の行
- **位置は固定でなく、見出しの文字を探して決める**(`control_sheet_parse.py`)。「管理No」「セットアップファイル」「NO」「工程名」「作業要領」「ライン名」「組立工程へ」。見出しの前後の空白(全角を含む)と、全角・半角・大文字小文字の違いは無視する(`fold`)。値は見出しの1つ下のセル。見つからないシートはエラー(理由に見出しの名前を出す)

### 読み方

- **ファイルNo.**: シート名。前後の空白を除き、全角を半角に、英字を大文字に、数字だけなら 0 で埋めて4桁(722 → 0722)。A4 に値があれば同じ規則で直してシート名と比べ、違えばそのシートはエラー(空なら比べない)。シート名がファイルNo.の形(4文字の英大文字と数字)でなければ飛ばす(「Sheet1」など。理由を出す)。同じファイルNo.のシートが複数あれば、2つ目からエラー
- **管理No**: L2 の値(文字。数なら整数の文字)
- **工程の行**(固まりごとに1行): A列(NO の列)に番号があるセルが固まりの始まりで、固まりはその結合の範囲(結合が無ければその1行)。番号は8より多くてもよい。「組立工程へ」の行の手前まで。1つも無ければエラー。上限は 100 行(`MAX_ROWS`)
  - 工程名: B列の固まりの中のセルの文を上から改行でつなぐ。「社内」「社外」だけの行は区分に入れて工程名から外し、すぐ下の「INTERNO」「EXTERNO」だけの行も外す
  - 作業要領: 固まりの中の1行ごとに、作業要領の列(C)からライン名の列(H)の手前(C〜G)までの文を**空白でつないで**1行の文にし、上から改行でつなぐ。前後の空の行は除き、途中の空の行は残す
  - ライン名の欄を使うか: H列の固まりのセルに斜線の罫線(右上がり・右下がり)があれば使わない、無ければ使う
  - 中身の無い固まり(工程名も作業要領も空)も、空の行として取り込む(斜線の設定は読む)
  - 工程名のベトナム語、将来の自動入力のための対応は、ブックには無い。**今の内容に同じ工程名の行があれば、その行のベトナム語と対応を引き継ぐ**(`control_sheet_carry.py`)。合わせ方: 1. 同じ位置(行の番号)で工程名が同じ行を先に合わせる。2. 残りは、工程名がちょうど1つだけ一致する行と合わせる(新しい内容の側にも今の内容の側にも、その工程名の残りが1つだけのとき。2つ以上あるときは、どれか決められないので引き継がない)。工程名が空の行は引き継がない。新規のシートは空(なし)
  - 工程名は 100 文字、作業要領は 2000 文字まで(超えたらそのシートはエラー)
- 文の前後の空白は除く。数式のセルは保存されている値(openpyxl は `data_only=True`、xlrd は保存された値)。マクロは動かさない(`keep_vba=False`)

### 確かめる → 登録

1. ブック(.xls、.xlsx、.xlsm)を選ぶと、**確かめるだけ**の結果を出す(`POST /api/admin/control-sheets/import/preview`。DBには書かない)。シートごとに、ファイルNo.、状態(新規 / 変更あり / 変更なし / 飛ばした / エラー)、理由、行の数。変更ありは、今の内容との違い(管理No、行の数、行ごとの工程名・作業要領・区分・ライン名の欄。1シート 50 件まで)を見られる
1a. 確かめる画面の「違い」に、**引き継いだ行の数と、引き継げずに消えるもの**(工程名が変わった・なくなった行のベトナム語と対応。今の内容の行の番号つき)を出す(`carried`、`lost`)。引き継いだ内容は「違い」に出さない。引き継いだ内容と同じブックは「変更なし」になる
1b. 確かめるときに、送られたブックの **SHA-256** を返す(`sha256`。ブックは残さない)と、シートごとの今の版(`current_version`)を返す
2. **変更ありのシートで、今の内容(最後の版)が管理画面で作った・直したもの(action が save か copy)なら、「管理画面で直した内容を上書きします」と出す**(選んだシートの合計も警告)。最後の版が取り込みなら出さない
3. 登録するシートを選び(初期値は新規と変更あり)、「登録」を押す(`POST .../import/apply`。同じブックをもう一度送る。サーバーはブックを残さないため)。**登録の本文の指定(`ApplyMeta`)に、登録するファイルNo.・確かめたブックの SHA-256・ファイルNo.ごとの確かめたときの状態(新規 / 変更あり)と今の版を入れる。サーバーは、送られたブックの SHA-256 が違えば「確かめたブックと違います。もう一度確かめてください」と断り(409)、確かめたときと同じ読み方で読み直して、選ばれたファイルNo.の状態か版が確かめたときと変わっていれば(間に管理画面で直された、など。1つでも)、何も登録せず「確かめたあとに、ファイルNo.(…)の内容が変わりました。もう一度確かめてください」と断る(409)。** 断られたら、画面は確かめる結果を消して、確かめ直してもらう。**登録は1回の取り込みを1つの単位として履歴に残す**(表 `control_sheet_imports` = 誰が、いつ、どのブック名で、何シート中何件。マイグレーション 0022)。取り込んだ版は `action = import`、`import_id` が取り込みの番号。audit_log に、取り込みの全体(`control_sheet_import_batch`)と、ファイルNo.ごと(`control_sheet_import`)の両方を残す
4. 管理画面で手で直した内容も、取り込みで上書きされる。**上書きの前の内容は履歴(版)から見られ、戻せる**(AD-27 の履歴の仕組み。履歴から版を読み込んで保存すると新しい版になる)。内容が同じ(変更なし)なら版は足さない
5. 確かめる結果は画面にだけ持つ。登録の時点で、上の照らし合わせと、今の内容との比べ直しをする

### 大きさと速さ

- 本文はブックそのもの(multipart にしない。依存を増やさないため)。登録の本文は、先頭 10 桁(JSON の長さ)+ 選んだファイルNo.の JSON + ブック
- **この2つのパスだけ、本文の上限を広げる**: config.toml の `[server] control_sheet_import_max_mb`(既定 50。ほかは `max_body_mb` = 5)。`BodyLimitMiddleware` の `path_limits`。超えたら 413。シートは最大 2000(`MAX_SHEETS`)。ブックを読めない(形式が違う・壊れている・パスワード付き)ときは 409(例外の種類だけ。中身は出さない)
- 1000シート(各12固まり)の .xlsx(約1.3MB): 確かめる 約5秒、登録 約6秒(開発PC。pytest `test_a_thousand_sheets...`)。.xls は読みが約2秒。読むのは書き込みのロックの外で行う
